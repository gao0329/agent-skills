# Literature Download

根据研究主题检索文献，只收录实际取得并通过验证的全文。原版全文 PDF 优先，其次为正文完整且可可靠渲染的 XML 全文；只有摘要、只有全文链接或获取失败的文献不属于成果。

## 检索前界定研究范围

- 对干预效果类问题，从用户描述中提取 PICO：人群、干预、对照和结局。
- 已明确的信息直接采用；仅对影响检索范围的关键歧义向用户澄清。
- 不擅自增加年份、随访时长或研究类型限制。
- 根据 PICO 选择检索概念，不强制将四个要素全部加入检索式。
- 将研究范围、实际检索式及检索日期记录在输出中，供后续筛选和综述写作使用。

## 使用流程

运行依赖：在执行脚本的 Python 环境中安装 `pypdf`（可在本技能目录运行 `python -m pip install -r requirements.txt`）。XML 全文转 PDF 还需要脚本能找到 Chrome/Edge；脚本检查 Windows 常见 Chrome/Edge 路径及 Linux 常见 Chrome/Chromium 路径，其他安装位置需调整脚本的 `find_chrome()`。

1. 阅读 [固定输出规范](references/output-contract.md)。单主题、多主题、多轮补充检索均使用同一任务目录和同一数据规范。
2. 将中文主题转换为少量英文关键词。脚本将每个主题的各词用 `AND` 连接，不支持直接传入完整布尔检索式，也不自动筛选年份或研究类型。多个主题通过重复 `--topic` 一次提交并合并去重，不按主题分别创建交付目录。
3. 调用本技能目录下的 `scripts/pipeline.py`。下例从技能目录执行；从其他目录调用时使用脚本的绝对路径。

   ```sh
   python scripts/pipeline.py --topic "hypertension telemonitoring" --topic "hypertension selfmonitoring" --scope "高血压远程监测与自我监测" --max 100 --out "本次文献"
   ```

4. 核对固定结构、成功记录和 PDF 是否一一对应，再向用户提供全文数量、清单和任务目录链接。最终回复及项目历史记录只引用已验证的全文集合。

常用参数：

- `--topic`：英文主题关键词，按空格、逗号或分号分隔；可重复传值。
- `--max`：每个主题最多取回的候选篇数，默认 100，不是保证取得的全文篇数。
- `--scope`：研究范围，可用中文；未指定时采用主题信息。
- `--out`：本次任务根目录；默认在当前工作目录创建带时间戳的目录。
- `--resume`：未完成任务从系统临时区的检查点恢复，必须使用原任务相同的主题、上限、范围及输出目录，严格核对完整参数并重新验证已有文件。已完成任务则检查当前清单、CSV 与 PDF，验证通过后直接返回，不重新检索；此时不依赖已清除的检查点，也不再与旧任务参数比较。
- 旧参数 `--skip` 不再支持，改用 `--resume`。旧 `_meta.json` 或混合产物目录不能作为新规范的检查点。

## 输出与汇报

任务根目录固定为 `文献清单.md`、`文献索引.csv` 和 `论文/` 三项，详细章节、字段及文件命名见 [固定输出规范](references/output-contract.md)。没有取得全文时也保留这三项，清单说明全文 0 篇，索引只保留表头。

- 清单首行直接使用 `# 文献清单`，仅包含可读的研究范围、检索记录、汇总、全文表格与说明，不嵌入 JSON 注释、机器参数、哈希或重复题录。CSV 是持久化题录的唯一来源；校验及补充检索均从 CSV 恢复题录，原查询从清单的可读检索记录中读取。
- 清单、索引、最终回复及项目历史（包括 `.workbuddy/memory/`）中的文献条目，全部从同一份通过验证并去重的全文记录生成。
- 不另建全局文献历史数据库；仅在原有任务历史机制中记录成功全文。
- 未获取全文的文献不得写入题名、PMID、DOI、摘要、逐篇失败记录或待补名单；不生成摘要 PDF。
- 不另建 `lit_*` 交付子目录、证据摘要、总索引或其他临时产物。候选题录和恢复数据仅用于外部临时检查点，正常完成后清除。
- 可记录检索任务信息、全文总数及两类全文数量。任务故障用任务层面的说明表达，不逐篇暴露未获全文的候选，不将未知原因推断为订阅或版权限制。
- 不自动覆盖或迁移已有混合目录和旧历史；清理旧产物属于独立迁移任务。

## 获取与验证

- 使用 PMC 官方开放全文和 Europe PMC 获取可用全文，不绕过验证码或付费墙。
- 取全文前先通过 Europe PMC 批量检索（一条 OR 查询携带约 50 个 PMID）预取 PMID→PMCID 映射，无 PMC 收录的候选不再逐篇发起取全文请求；批量结果不校验 DOI，身份仍由逐篇流程复核。网络波动导致批量预取失败时逐篇兜底，不中断任务。
- HTTP 4xx 视为确定性失败立即放弃，仅 5xx 与连接类错误重试且退避 0.5 秒；并发下载 10 路，进度每 10 组输出一行，避免长时间无输出被误判为卡死。
- 优先尝试原版 PDF，其次尝试 XML 全文并渲染；不能仅依据 `isOpenAccess` 字段排除获取机会。
- PDF 必须能解析、含有正文并与目标文献身份相符；文件头、大小、HTTP 成功或文件存在均不足以认定成功。`pypdf` 是必需验证依赖，缺少时在开始任务前报错，不能降级为仅检查文件头和大小。
- XML 必须有正文，只有摘要即排除。未支持的图、表、公式等内容不能静默丢弃后标为全文；当前转换器保守拒绝无法可靠保留的内容。
- XML 渲染依赖 Chrome/Edge。缺少浏览器时仍可取得原版全文，并记录任务层面的渲染限制；不降级生成摘要。
- 自动检查不能证明全文绝对完整。交付前抽查身份、正文和关键内容；发现缺页、正文缺失或渲染丢失的文件应剔除并同步重建清单和索引。
- 校验以 CSV 为题录来源，重新检查当前 PDF 的身份及正文，并核对清单表格、计数和链接的一致性。清单可读文字不要求与脚本模板逐字一致，不以历史 SHA 摘要值判断当前文件是否合格。旧清单首行注释可被兼容跳过，但其中 JSON 不参与校验或恢复，新生成清单不再写入该注释。

维护接口或排查下载问题时，参阅 [接口与获取边界](references/api-boundaries.md)。
